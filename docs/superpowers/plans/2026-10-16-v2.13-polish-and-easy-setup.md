# v2.13 — UI polish and setup anyone can finish

**Goal:** Tasky feels finished on the device, and setup (calendar, GitHub streak, Claude Code) takes minutes from a phone or a computer, with no guessing.

**Starts after:** 2.12 is tested on hardware and released (flash once from the web: new partition table).

**Flash budget:** C6 Agents ≈ 94.5 % (≈ 110 KB free) after 2.12. UI polish should stay under ~25 KB. Measure after each task.

---

## Part A — On the device (UI/UX audit)

Every task keeps the 2.10 rule: **no full-screen repaint while you stay on a screen** (`full = !baseDrawn`, repaint only what changed).

### A1. Where am I? Carousel dots
- A row of small dots at the top of every carousel screen (as on Agents): one per screen, current one filled. Screens opened from More show none.
- Drawn by the screen-enter path (`showHint` neighbour), 8 px tall, inside the 12 px safe area. Screens whose title sits at y≈34 move it down 4 px if needed.

### A2. Icon hints instead of words
- A tiny knob glyph (circle + arrow) for "turn", a dot-in-circle for "press", a long bar for "hold". The hint pill reads "⟳ time · ● start" instead of "Turn: time  Press: start".
- Glyphs are 12×12 1-bit bitmaps (like the agent sprites), drawn inline by `drawHint`. Same 3-visits rule.

### A3. No flicker anywhere
- Weather, Agenda, Stats, Calendar day view, Update and QR still repaint the whole screen when data arrives. Give them the same partial redraws (data area only).
- Audit with a grep for `fillScreen` reached while `baseDrawn` is already true.

### A4. One look for every screen
- Shared header: small caps title in 9pt muted at y≈28 (or none), content starts at y≈44. Today some screens use 12pt bold titles, some none.
- Shared row style for lists (Settings, Focus, More): same height, same selection pill.

### A5. You pressed: visible feedback
- Without a buzzer a press is silent. The selected row/pill flashes inverted for ~80 ms on every press (in `uiTick`), and the light bar blips (if not in focus mode).

### A6. Home that tells your day
- Under the clock: today's streak square (its green level) + "3 sessions · 75 min". A thin progress bar for the day (focus minutes vs a daily goal, default 120 min, settable on the web).

### A7. Settings you can see
- Brightness and LED as a 10-step bar while editing; Work/Break minutes with ± arrows. Values change live (brightness applies while you turn).

### A8. Rest screen with phrases (the old calm design)
- Ambient = big clock, date, and one quote with its author (the Phrases data), changing every 2 min. No tasks or weather clutter. Home keeps the full glance.

### A9. Timer that knows your task
- Inside the ring: the task you're focusing on (if any) and today's sessions as dots (already there) plus "#3 today".

### A10. Agent banner on any screen (Agents edition)
- When an agent starts waiting, a slim amber banner at the top for 5 s ("my-app needs you") on whatever screen you're on, plus the breathing light. Permission questions still jump to the card (2.12).

### A11. Quick settings
- Long press on Home: a 3-item sheet (Brightness, Dark/Light, Focus on/off). Replaces "long press = Tasks" (Tasks is in the carousel). Update the Home hint, MANUAL and tour.

### A12. Night mode
- Outside your workday hours (`dayStartHour`/`dayEndHour`, already in settings), backlight and LED drop to a night level. Hardware note: the backlight is on/off only on the current boards (BLK tied to VCC); night mode dims the LED and switches to a darker palette until a board with backlight PWM (Tasky Go plan).

### A13. Weather is only weather
- Without data, Weather shows the **time** (an old fallback) instead of telling you what's missing. The clock already lives on Home. Empty states instead: "Set your city: tasky-flash.vercel.app" (no city), "Waiting for Wi-Fi" (city set, offline), "Updating..." (fetching). Never the clock.

### A14. Streak: yours and GitHub's
- Two pages on the Streak screen with two dots at the top: **Personal** (Tasky activity: focus sessions, tasks, agent answers) and **GitHub** (your contributions). Turn the knob to switch pages; the grid, legend and totals follow.
- GitHub history: the last 84 days from the public events API (`/users/<name>/events`, up to 90 days / 300 events, no token), counted per day and stored as its own grid (`ghStreak[84]` in NVS, refreshed every few hours). Today's count keeps updating as now.
- Drop the hidden "press to cycle a day's level" (manual edits made both grids lie); press opens a one-line detail for the selected day.

## Part B — Setup anyone can finish

### B1. Calendar, step by step (computer and phone)
- The Calendar step asks **"Which calendar do you use?"** with three buttons: Google, iCloud, Outlook. Each shows 3 short illustrated steps (inline SVG diagrams of the provider's menus, not screenshots) and a direct link:
  - Google: calendar.google.com → ⋮ next to the calendar → Settings and sharing → "Secret address in iCal format".
  - iCloud: Calendar app → share icon → "Public Calendar" → copy link (webcal://).
  - Outlook: Settings → Calendar → Shared calendars → Publish a calendar → ICS link.
- **Test it on the device:** new USB command `TASKY CALTEST` (needs Wi-Fi): Tasky downloads the feed and answers `{"ok":true,"events":5,"next":"Standup 10:00"}` or a clear error (404, not iCal, too big). The step shows "Found 5 events this month. Next: Standup at 10:00 ✓".
- Accept `webcal://`, strip spaces, warn on `/embed` and non-iCal URLs before sending.

### B2. GitHub streak without guesswork
- The GitHub step validates the username in the browser (`api.github.com/users/<name>`, CORS allowed) and shows the avatar + name: "Is this you?".
- Preview of the last 12 weeks of contributions as the same green squares Tasky draws (public events API), so you see what the Streak screen will show.
- Explain the streak in one line: "Green gets darker with your GitHub contributions and your focus sessions on Tasky".

### B3. The phone path (no computer)
- The phone portal (QR on Tasky) gets the **same steps and helpers** as the web wizard: Wi-Fi, calendar (with the provider helper), GitHub, city, screens, phrases. Plain HTML served by the device, mobile-first, **English/Spanish** by the phone's language (`Accept-Language`), so it stays small.
- Flash cost: the portal HTML is gzip-compressed in flash (`PROGMEM`, served with `Content-Encoding: gzip`). Target ≤ 20 KB.
- **Later (needs research):** Improv Wi-Fi over Bluetooth for Android Chrome (Web Bluetooth). iOS Safari has no Web Bluetooth, so the QR portal stays the iPhone path.

### B4. Connect Claude Code in one step
- **Claude Code plugin** (docs: code.claude.com/docs/en/plugins, plugins-reference, plugin-marketplaces):
  - Repo root `.claude-plugin/marketplace.json` (name `tasky`) listing one plugin in `claude-plugin/`:
    - `.claude-plugin/plugin.json` (name `tasky`), `hooks/hooks.json` with the five hooks calling `python3 "${CLAUDE_PLUGIN_ROOT}/tasky_agent.py" …`, and the script itself (single source: `companion/tasky_agent.py` moves there; `companion/` keeps README + tests).
    - Skill `/tasky:status` that runs `tasky_agent.py status` and explains fixes.
  - Install from Claude Code: `/plugin marketplace add arampersand/tasky` then `/plugin install tasky@tasky`. Updates come with `/plugin update`. No settings.json editing, no curl.
  - Validate with `claude plugin validate`; CI runs it.
  - `install.sh` stays for people who prefer it (and for other agents); both paths documented, the plugin first.
- **`tasky_agent.py doctor`:** checks Python, finds the port, reads the firmware edition/version, tells you if the port is busy and by which app (`lsof`), whether hooks are installed (plugin or settings.json), and prints the one fix to run.
- **Web Agents step:** shows the two plugin commands with copy buttons (curl as "other ways"), then "Disconnect" so Claude Code can reach Tasky. After the user restarts Claude Code, the Tasky shows a "Claude Code connected" card (sent by a `SessionStart` hook).
- **Busy-port message on the device side:** when the web page holds the port, the Agents screen says "USB in use by the setup page" (Tasky can't tell who holds it, but it can tell that agent lines stopped while TASKY? keeps coming).
- Windows (later): companion transport over a localhost socket instead of a Unix socket, pyserial for the port; plugin hooks use `python` instead of `python3`.

### B5. Onboarding that starts by itself
- **Can plugging Tasky in open the setup page on the computer?** Not on these boards. Chrome's "go to this page" pop-up needs a WebUSB descriptor, and the XIAO C3/C6 USB port is a fixed Serial/JTAG block whose descriptors can't be changed (nor can it pretend to be a USB stick with a link on it). So Tasky has to point you there itself:
  - **Not set up yet** (no Wi-Fi saved): Home shows "Set me up" with the address `tasky-flash.vercel.app` big, plus a QR code of the phone portal. The tour's last step says the same.
  - The web page detects a plugged-in Tasky it already knows (2.9 feature) and jumps straight to **Set up** if the device reports no Wi-Fi.
  - Flashing from the web flows straight into the setup steps (no scrolling to a second section).
- **Take more from the computer / phone automatically:** time zone and clock (done), city from location (done), Wi-Fi network list (done). New: the computer's language picks the portal/wizard language; the phone portal offers "Use this phone's location" for weather (Geolocation over the captive portal needs HTTPS, so it falls back to typing the city).
- **Phone (Android):** Improv Wi-Fi over Bluetooth from tasky-flash.vercel.app in Chrome for Android, so Wi-Fi setup needs no QR. iPhone keeps the QR portal (no Web Bluetooth on iOS).
