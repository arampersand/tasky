# v2.12 — Computer companion: agent cards, approvals from the knob, F-row Controls

**Goal:** make Tasky for Agents something you actually use all day next to the computer. Each agent gets its own card with a little pixel character. Tasky can **answer Claude Code permission prompts** (allow / deny) with the knob. Controls becomes a Mac/Windows function row. Hooking agents up takes one command.

**Edition:** Tasky for Agents (`xiao_c3_agents`, `xiao_c6_agents`). The original Tasky only gets the partial-redraw and shared UI pieces.

**Flash budget:** C6 Agents is at 97.1 % (≈ 57 KB free) after 2.11. See Task 0.

---

## What Claude Code allows (hooks reference, checked 2026-10-16)

- **`PermissionRequest` hook** fires when Claude Code is about to ask for permission. A command hook may block (default timeout 600 s, settable with `"timeout"`) and answer with
  `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"|"deny"}}}`.
  `updatedPermissions` can switch the session mode, for example `{"type":"setMode","mode":"acceptEdits","destination":"session"}`.
- Hook stdin carries `session_id`, `cwd`, `hook_event_name`, `permission_mode`, plus `tool_name` / `tool_input` for tool events, and `notification_type` for `Notification`.
- **Not possible:** answering an `AskUserQuestion` multiple-choice prompt, choosing the exact "don't ask again" entry of the permission menu, or sending a new prompt into a running session. Tasky won't promise these.
- If the hook times out or Tasky isn't there, Claude Code falls back to its normal prompt. Nothing is lost.

Source: https://code.claude.com/docs/en/hooks.md (re-check the schema before implementing. Fields named above must match the live docs.)

## Task 1 — Companion broker (one owner for the USB port)

Today every hook opens the serial port, writes one line and closes it. An approval needs a hook to **wait** for the answer while other sessions keep reporting, so one process must own the port.

- `companion/tasky_agent.py daemon`: owns the port, listens on a Unix socket (`~/.tasky/agent.sock`; named pipe on Windows later), forwards `TASKY AGENT …` lines and routes replies.
- Hooks (`tasky_agent.py hook …`) talk to the socket and **start the daemon on demand** if it isn't running. Hooks still never fail the agent: no Tasky means exit 0 in under 1 s.
- **Drop the pyserial dependency:** open `/dev/cu.usbmodem*` / `/dev/ttyACM*` with `termios` (stdlib only), with Espressif VID detection via `ioreg` / `sysfs`. Keep pyserial as an optional fallback (and for Windows).
- The daemon reconnects when Tasky is unplugged and plugged back, and exits after 2 h with no sessions.
- Tests: `pytest` with a fake serial pair (`pty.openpty()`). Cover concurrent hooks, approval round-trip, Tasky missing, and replug.

## Task 2 — Approvals from the knob

**Protocol** (firmware `agents.h`, documented in `companion/README.md`):

```
→ TASKY ASK {"id":"<req>","session":"<session_id>","label":"<project>","tool":"Bash","detail":"npm test","options":["Allow","Deny","Allow edits"]}
← @tasky {"answer":{"id":"<req>","choice":0}}        (or "choice":-1 on timeout / dismissed)
→ TASKY ASK-CANCEL {"id":"<req>"}                     (answered in the terminal first)
```

- Firmware: a pending-question slot per session (max 4). The light breathes and Tasky beeps once (muted during focus). The Agents card shows the question. **Turn** picks an option, **press** answers, **long press** dismisses (Claude asks in the terminal as usual).
- `detail` is cut to fit (ASCII, ≤ 60 chars): the Bash command, the file path for Edit/Write, or the URL for WebFetch.
- Hook: a `PermissionRequest` hook calls `tasky_agent.py ask`, which waits up to `TASKY_ASK_TIMEOUT` (default 120 s, below the hook's 600 s) and prints the decision JSON. "Allow edits" sends `behavior: allow` plus `updatedPermissions` setMode `acceptEdits` for the session.
- **Safety:** only `allow`/`deny` for the one request. Nothing auto-approves. A timeout or an unplugged Tasky falls back to the normal terminal prompt. The README states plainly that anyone who can press the knob can approve.

## Task 3 — Agent cards with a pixel character

- Agents screen = one card per session: project name, state, last message, and a **16×16 pixel character drawn for Tasky** (our own design, not Anthropic's mascot), scaled ×4. Turn = next card. A dot row shows how many sessions there are.
- States animate with 2–3 frames (≈ 2 fps, partial redraw of the sprite box only): working (typing/bouncing), **waiting** (waving + light breathing), done (happy, check mark), question (raised hand plus the options under it).
- Sprites live as 1-bit bitmaps in `agents_sprites.h` (≈ 32 B per frame), tinted per state.
- Partial redraws, as in 2.10: changing cards repaints the card area only, never `fillScreen` while on the screen.

## Task 4 — Controls as a function row (Mac / Windows)

- A horizontal strip of key icons like the Mac's top row, with the selected key big in the middle: **Brightness, Mission Control / Task View, Spotlight / Search, Dictation, Previous, Play/Pause, Next, Mute, Volume, Desktop ←, Desktop →, Screenshot, Lock**.
- **Turn** = pick a key, **press** = send it. Brightness and Volume are dials: press to grab (the knob turns the value), press again to let go.
- **Mac / Windows** switch (long press on Controls, saved in NVS, also in the web setup). Media keys are the same on both. Shortcuts differ:

| Key | macOS | Windows |
|---|---|---|
| Mission Control / Task View | Ctrl+↑ | Win+Tab |
| Spotlight / Search | Cmd+Space | Win+S |
| Dictation | consumer Voice Command | Win+H |
| Desktop ← / → | Ctrl+← / Ctrl+→ | Ctrl+Win+← / → |
| Screenshot | Cmd+Shift+4 | Win+Shift+S |
| Lock | Ctrl+Cmd+Q | Win+L |

- Apple-only keys (Do Not Disturb, Launchpad, keyboard backlight) aren't in the HID standard. Leave them out rather than ship keys that do nothing.
- **macOS "Keyboard Setup Assistant"** appears the first time you pair (Tasky is a keyboard to macOS). Controls shows a one-time note, and the guide says: close it, the shortcuts work anyway. We won't spoof Apple's vendor ID to hide it.
- Partial redraws only.

## Task 5 — Hook up agents in one command

- `web/public/agents/install.sh` (served by the flasher site): puts `tasky_agent.py` in `~/.tasky/`, merges the hooks into `~/.claude/settings.json` with a backup (`settings.json.tasky-backup`), never touches other keys, and is idempotent. `--uninstall` removes exactly what it added.
- Web setup: a new **Agents** step (Agents edition only) shows the command with a copy button and a **"Send a test"** button. The page itself sends `TASKY AGENT` over Web Serial, so you see a card appear without any terminal.
- The empty Agents screen says "Set up agents: tasky-flash.vercel.app".
- `companion/README.md` is rewritten around the one command; manual steps go in a details block. Windows: PowerShell `install.ps1` once Task 1 has a Windows transport (otherwise documented as macOS/Linux only for 2.12).
